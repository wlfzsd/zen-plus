# zen-plus v3.1.8 vs 官方 v0.27.1 —— 引擎内存与效率对比（2026-10-14）

## 方法
- 双 git worktree（zen-plus eb309f4 / 官方 v0.27.1=195d2ca），同一份 abbench 基准（同字节），只用公共 API。
- 同机、同 13 个过滤列表缓存、同语料（35,358 probes/遍）、单线程。
- 装载=生产同构（13 列表 cache.txt → asset 分流 → 跨列表去重 → ParseRule → Compact）。
- 内存两轮零波动；基准 benchtime=2s（全语料单遍/迭代）。

## 内存（装载后 GC×2 稳态）
| 口径 | zen-plus | 官方 v0.27.1 |
|---|---|---|
| live 堆 | **135.5 MB**（两轮 135.5/135.5） | 150.9 MB（150.9/150.9） |
| 实装规则 | **566,656** | 557,166（解析失败静默丢弃 11,890） |
| 每条实装规则驻留 | **239 B** | 271 B |
| 装载峰值堆 | 311.2 / 304.8 MB | 283.0 / 279.1 MB |
| heapSys | 335.8 / 323.7 | 299.8 / 291.7 |
| 装载耗时 | 1037 / 1059 ms | 785 / 795 ms |

要点：zen-plus 在多装 9,490 条规则的前提下 live 低 10.2%；官方解析丢弃数是 zen-plus 的 4.9 倍。官方装载更快（少解析 1.2 万条）。峰值/heapSys 官方更低，同样源于少装规则与解析路径差异。

## 自我对比（相对 zen-plus v3.1.7 引擎态 81a96f5）
live 166.6→135.4 MB（**-18.7%**）、装载峰值 422.5→363.6 MB（-58.9 MB）、装载 1882→1828 ms。
改动：打包字节前缀（1B/token，转义对双射）＋反向索引强制择一分支集＋前缀折叠。

## 判定面
两树各自的拦截判定测试全集通过；zen-plus 侧历次改动均以 133,212 请求黄金对拍（FNV 逐位一致）与双引擎逐元素差分背书。
