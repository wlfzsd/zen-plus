# 补充对比测试（2026-10-10 下午）：关上游代理网络对比 + 去 AdGuard 订阅内存对比

## 一、禁用上游代理的网络对比（同机同规则全新配对）

口径：plus v3.1.0 关闭上游代理（直连出站）vs 官方 v0.26.0，双方都是直连出站——隔离"纯引擎+应用"差异。顺序：直连锚点 → N1(plus-nochain 6 轮) → 直连锚点 → N2(官方 6 轮) → 直连锚点；900 请求 0 失败；过滤器 0 漂移。

| 臂 | 冷连接 TTFB 中位 | 热连接 TTFB 中位 | 热连接 Total 中位 | CPU |
|---|---|---|---|---|
| 直连锚点（3 段） | 75-92 ms | 28-32 ms | 36-38 ms | — |
| **N1 plus-nochain** | **41 ms** | **31 ms** | 36 ms | **2.97 ms/req** |
| **N2 官方** | 45 ms | 30 ms | 34 ms | 3.28 ms/req |

结论：
- **热连接 31 vs 30ms（差 1ms，噪声级）；总耗时 36 vs 34ms（差 2ms）**——关掉上游链后，plus 与官方的实际网速无实质差异（所有差异 ≤ 直连锚点自身波动 28-32ms）。
- **冷连接 plus 反而快 4ms（41 vs 45）**——plus 的连接建立路径（含 h1 镜像腿）不劣于官方。
- 分站点：10 站全部 ±10ms 内，bilibili 官方反而最慢（336 vs 310）、zhihu plus 略慢（172 vs 152）——均与直连锚点波动同量级，无系统性差异。
- **CPU：plus 2.97 vs 官方 3.28 ms/req（plus 低 9.5%）**——纯应用开销 plus 更低。
- 结合主测试：plus 开上游链的代价 = 热连接 +2~6ms / 冷连接 +14ms；而官方根本没有上游链能力。

## 二、临时禁用 AdGuard 订阅的内存对比（隔离纯引擎结构差）

口径：引擎级生产同构装载，跳过三个 AdGuard 品牌列表（AdGuard Base / Spyware / CN），其余 10 列表两侧完全同源（同一批 cache.txt）；各 3 次全新进程取值（-count=1 防缓存）。

| | plus v3.1.0 | 官方 v0.26.0 | Δ |
|---|---|---|---|
| 驻留堆（3 样本逐字节一致） | **63.5 MB** | **77.9 MB** | **plus 省 14.4MB = -18.5%** |
| 装载规则数 | 215,467 | 212,325 | plus 多 3,142 |
| 解析失败 | **47** | 3,189 | 官方多丢 3,142 |
| 装载耗时 | ~760ms | ~620ms | plus 慢 ~140ms（装载期去重+索引） |

结论：
- **消除"多救回规则"变量后，纯引擎结构内存差反而更大：-18.5%**（13 列表全量口径为 -10.5%）——plus 的节点瘦身（96B→64B）、分配池化、覆盖去重的优势在小规则集上占比更高。
- 即便只剩 EasyList 这一个非 AdGuard 品牌列表，官方仍丢 3,189 条（EasyList 3,139 条解析失败），plus 仅 47 条——官方解析器的静默丢弃是普遍现象，不止 AdGuard 系列表。

## 三、68KB 爆炸 URL 实测（2026-10-10 补充，回应"官方版测过吗"）

**测了。** 双 worktree 同一份基准（语料 545K 规则生产同构装载后，单请求喂 68KB 对抗性 URL，形态与 plus 修复提交 f5c7ba3 的回归测试 longD 一致：`www.youtube.com/watch?v=<重复填充>` 共 68,039 字节）：

| 引擎 | benchtime | 结果 |
|---|---|---|
| **plus v3.1.0** | 5 次迭代 | **125.4 ms/op**（10.2MB、5,185 allocs——含每请求 68KB URL 的 Clone 开销）|
| **官方 v0.26.0** | 5 次迭代 | **10 分钟超时未能完成**（被限时终止时已烧 580+ 秒 CPU）|
| **官方 v0.26.0** | 1 次迭代 | **8 分钟超时仍未完成单次**（被终止时已烧 ~450+ 秒 CPU，WS ~373MB）|

结论：**官方 v0.26.0 对该类 URL 单请求成本 > 8 分钟 CPU（实测下限），plus 0.125 秒——差距 >3,800 倍（下限口径）**。代码级核验：上游 v0.25.1→v0.26.0 对 internal/ruletree 完全零改动（git diff 为空），遍历爆炸缺陷在官方最新版仍在；plus 的修复（全状态记忆化 + 4096 字符截断 + 尾通配吞并，提交 f5c7ba3/b3fcee3/de43a5）是唯一解。基准装置：ab_bench\src\ab_explosive_test.go（两树同字节）。

注：plus 的 125ms/op 中大头是测试装置每迭代 Clone 68KB 请求（~1-2ms）+ 真实引擎成本 ~1ms 内与 545K 规则装载态的匹配开销；官方不是"慢"而是**成本随 URL 长度非线性爆炸**（这正是当年线上 183MB 巨块内存事故的根源）。
